# Статус проекта GlobalFront

> Последнее обновление: 2026-08-08; Unity: `6000.5.6f1` с URP
> Стадия: локальный RTS-прототип, pre-alpha

## Краткое резюме

GlobalFront имеет детерминированное ядро на 20 Hz, headless `MatchServer` и локально управляемый RTS-прототип. Базовая логика и клиентские очереди команд покрыты EditMode-тестами: **102/102 теста пройдены 08.08.2026**.

Проект ещё не является сетевой RTS. Клиент создаёт shadow `MatchServer` только для регистрации юнитов с совпадающими id; команды, перемещение, авто-выбор целей и бой выполняются локально. Транспорт, серверный host loop, сериализация снапшотов, prediction и reconciliation отсутствуют.

## Реализовано

| Область | Состояние |
|---|---|
| Детерминированные координаты, перемещение и бой | Реализовано и протестировано. |
| Команды `Move`, `Attack`, `Stop` на сервере | Реализовано; команды валидируются и упорядочиваются детерминированно. |
| `MatchServer` без Unity-зависимостей | Реализован; поддерживает state, команды, movement и combat. |
| Локальный RTS-прототип | Реализован: выбор, перемещение, атака, камера, HUD и процедурный мир. |
| Shadow-регистрация клиентских юнитов в сервере | Реализована; пока не является авторитетной синхронизацией. |
| EditMode-покрытие | 102/102 пройдено. |

## Не реализовано

| Область | Состояние и риск |
|---|---|
| Авторитетный локальный host | Не начат. Без него нельзя проверить фактический паритет Client/Server. |
| Транспорт и сессии | Не начаты. |
| Сериализация `ServerUnitSnapshot` | Не начата. |
| Prediction и reconciliation | Не начаты. |
| PlayMode-тесты | Не добавлены; bootstrap и ввод не покрыты автоматизацией. |
| Игровой контент | Сцена генерируется кодом; prefabs, ScriptableObject-данные и производственные ассеты отсутствуют. |
| Команды `AttackMove`, `Guard`, `Build`, `Produce`, `UseAbility` | Типы перечислены, но payload и обработчики отсутствуют. |

## Важные ограничения прототипа

- Локальный игрок зафиксирован как `PlayerId(1)`; согласования идентичности игрока нет.
- `FormationSpacingMm` и скорость movement в prototype пока не централизованы.
- `GlobalFrontRuntimeBootstrap` создаёт временный мир при загрузке сцены; для меню и нескольких игровых сцен потребуется явная конфигурация.
- Временные препятствия визуальны: в детерминированном движении нет navmesh-поиска пути или разрешения коллизий.

## Ближайшие технические шаги

1. Создать `LocalMatchHost` вокруг `MatchServer`.
2. Передавать локальные команды в host и применять серверные снапшоты на клиенте.
3. Добавить тест паритета Client/Server по каждому тику.
4. Ввести фиксированный бинарный формат снапшота и версию протокола.
5. Добавить PlayMode-тест запуска `SampleScene` и основного цикла тиков.
6. Вынести общие симуляционные параметры в `SimulationConstants`.
