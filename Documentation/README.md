# Документация GlobalFront

> Единая точка входа для технической и проектной документации.
> Последнее обновление: 2026-08-08

## Назначение раздела

Папка `Documentation/` хранит документацию, не являющуюся игровым Unity-ассетом. Это предотвращает смешивание исходного кода, сцен и проектных решений, а также упрощает навигацию вне Unity Editor.

## Карта документов

| Документ | Назначение | Когда читать |
|---|---|---|
| [ARCHITECTURE.md](ARCHITECTURE.md) | Границы сборок, детерминизм и технический долг. | Перед изменением runtime-кода или сетевой архитектуры. |
| [PROJECT_STATUS.md](PROJECT_STATUS.md) | Реальное состояние прототипа, ограничения и ближайшие шаги. | Перед планированием задач и оценкой готовности. |
| [DECISIONS.md](DECISIONS.md) | Архитектурные решения в формате ADR. | Перед изменением ранее принятого направления. |
| [CHANGELOG.md](CHANGELOG.md) | Неверсионированные изменения и соответствие историческим Git tags. | Перед релизом, тегированием или подготовкой заметок к версии. |
| [ThirdPartyAssetsRegistry.md](ThirdPartyAssetsRegistry.md) | Источники и лицензии внешних ассетов. | До импорта любого внешнего материала. |

## Рекомендуемый порядок чтения

1. [Корневой README](../README.md) — открыть проект и запустить прототип.
2. [Статус проекта](PROJECT_STATUS.md) — понять текущую готовность.
3. [Архитектура](ARCHITECTURE.md) — изучить ограничения и границы модулей.
4. [Решения](DECISIONS.md) — проверить, почему выбрано текущее направление.
5. [Журнал изменений](CHANGELOG.md) — сверить историю и релизный контекст.
